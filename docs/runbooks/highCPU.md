# Runbook: HighCPU

## Симптом
На почту приходит алерт `[FIRING] HighCPU` для конкретного сервера.

## Диагностика
1. Зайти на сервер по SSH.
2. Запустить `htop` (или `top`), нажать `F6` и отсортировать по `CPU%`.
3. Найти процесс, который потребляет больше всего ресурсов.
4. Проверить логи этого процесса: `sudo journalctl -u <имя_сервиса> -n 50`.

## Решение
1. Если процесс завис — перезапустить сервис:
   `sudo systemctl restart <имя_сервиса>`
2. Если это плановая нагрузка (бэкап, обновление) — проигнорировать алерт.
3. Если это неизвестный процесс — проверить, не взломан ли сервер (команда `ps aux`).

## Эскалация
Если нагрузка не спадает более 15 минут — сообщить старшему инженеру.
